# Schema Comprehension Map (Agent Internal Reference)

This document is the agent's internal reference for Phase 3. It maps every table to its module, primary FKs, and which component IDs will read/write it. This is NOT shipped.

## Module Mapping (per system_topology.md Section 5)

- **Tenancy & Identity**: organizations, organization_templates, platform_admins, org_units, users, invitations
- **RBAC**: permissions, roles, role_permissions, user_roles, permission_overrides
- **Responsibility Engine**: responsibility_type_definitions, responsibility_assignments
- **Ledger & Wallets**: wallets, wallet_keys, ledger_adapter_config, token_transactions, chain_transactions, loans, compensation_policies
- **Task Engine**: task_type_definitions, tasks, nominations, task_proofs, task_peer_reviews
- **Workflow Engine (Engine 1)**: workflow_definitions, workflow_transitions, workflow_transition_log
- **Business Rules Engine (Engine 2)**: business_rules, business_rule_execution_log
- **Access Control Engine (Engine 3)**: access_control_rules
- **Reference Qualifier Engine (Engine 4)**: reference_qualifiers
- **Notification Engine (Engine 5)**: notification_definitions, notifications
- **Report Engine (Engine 6)**: report_definitions
- **Approval Chain**: approval_chain_definitions, approval_instances, approval_actions
- **Runtime Config**: rate_cards, cycle_calendars, system_jobs, integrations, activity_events, meeting_action_items, capacity_snapshots
- **Observability**: audit_logs

- MB-08 Earnings Summary (all closed tasks for credit total)
- LD-01 Lead Verification Queue
- LD-03 Task Creation Wizard
- DR-03 Org-wide Task View (all tasks across all org_units in Director's subtree)
- FN-01 Ledger Summary (closed tasks → credit disbursement)

**Write By**:

## Critical RPC Functions

### execute_workflow_transition(p_organization_id, p_entity_type, p_entity_id, p_to_state, p_actor_id)

Called by: Every Server Action that transitions state (MB-02 nominate → task status changes, MB-05 approve → VERIFICATION_PENDING, LD-01 sign-off → LEAD_SIGNED)

**Safety**:
1. Validates actor has allowed role for transition
2. Validates state machine path exists
3. Inserts workflow_transition_log
4. Calls apply_business_rules to execute side effects
5. Returns true/false to caller

**Never called directly on tables**: No `UPDATE tasks SET status = 'NEW_STATUS'` anywhere in codebase.

---

### apply_business_rules(p_organization_id, p_entity_type, p_entity_id, p_to_state)

Called by: execute_workflow_transition (always)

**Safety**:
1. Queries business_rules for entity_type + to_state + is_active
2. Executes each rule's action_type (INCREMENT_FIELD, CREATE_TOKEN_TX, SEND_NOTIFICATION)
3. Logs success/failure to business_rule_execution_log
4. Caller does NOT check individual rule success — rule failures are logged, not thrown

---

### batch_reverse_transfer(p_organization_id, p_cycle_start, p_cycle_end)

Called by: System job on monthly salary release

**Safety**:
1. For each user below threshold:
   - Issue LOAN_ISSUE token_transaction
   - Create loans record
2. For each user at/above threshold:
   - Issue SALARY_TRANSFER token_transaction
